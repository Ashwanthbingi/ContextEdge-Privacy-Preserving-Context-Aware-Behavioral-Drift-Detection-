# Evaluation methodology

The proposal explicitly contains no measured results. Reports in this repository are generated by executed experiments and always include their data source. No synthetic accuracy is presented as real-world accuracy.

## Controlled synthetic streams

`scripts/evaluate.py` trains separate models for five contexts on 400 generated normal observations each, then freezes their versions for evaluation. The normal generator has seeded autoregressive resource variation and explicit context/category signals. The profile manager uses the same train/holdout, scaling, Isolation Forest, GRU, ONNX export, parity and score calibration code as live training.

Twelve scenarios cover normal coding/browsing/media/idle/high-compute, short CPU/memory/I/O spikes, sustained CPU/memory shifts, a sudden multi-feature shift within a media profile, and a legitimate shifted regime followed by adaptation. Each has pre-change and post-change observations, deterministic injected intervals and explicit ground truth. The runner uses the actual engine; only the telemetry source and manual oracle context labels differ from a live run.

`decisions.csv` contains per-observation truth, predictions, context, scores, method, latency and adaptation status. `results.json` includes settings, seed, runtime, model sizes, parity results and scenario metrics. Each run uses its own isolated data/model directory. Stable file names in the report directory point to the most recent completed experiment, while run artifacts are versioned by timestamp.

## Definitions

- Anomaly precision, recall, F1 and false-positive rate use the binary calibrated anomaly decision. Counts are provided, and empty precision/recall denominators yield zero under the documented sklearn convention.
- Initial window/sequence/grace observations are excluded from scoring, not treated as correct negatives.
- The primary ground truth marks the raw injected interval. Feature/sequence tails may remain anomalous after the raw interval and are counted as false positives. This deliberately exposes detection latency and persistence effects.
- Drift detection delay is the first persistent decision during the changed interval minus the injection onset, in simulated sample seconds. Misses are null, never zero.
- False-drift observation rate is false persistent classifications divided by ground-truth non-drift observations. It includes recovery tails. Scenario rate indicates whether any such observation occurred; it is not the same as a rate of newly opened false episodes.
- The adaptation scenario is reported separately from aggregate AI accuracy because accepting a new normal changes the baseline. After explicit simulated approval, the shifted regime becomes normal; returning to the original regime is a new labelled change. Collection-to-acceptance time uses simulated time; actual training time is separately measured.
- Inference latency times normalization, Isolation Forest scoring, ONNX reconstruction and calibrated fusion, excluding telemetry, database writes and UI rendering. Summaries include mean, median, p95, max and count.
- Model sizes are file-byte counts. Full artifacts include PyTorch weights; deployment size counts ONNX and sklearn bundles.

## Actual laptop resource benchmark

`scripts/benchmark.py --seconds 30` runs the real collector/engine and measures process CPU user+system deltas, average/peak process RSS, system-wide CPU samples, observation count and inference latency when a calibrated context is actually used. CPU is reported as both percentage of one logical core and percentage of total logical CPU capacity. RSS includes loaded Python and ML libraries, not just model weights. Training and inference should not run concurrently with unrelated project benchmark jobs if comparing latency.

Without a trained real context, latency/model size are unavailable/zero; the report explains this. A separate synthetic-trained model run measures actual CPU inference latency but cannot establish real telemetry accuracy. Background user workloads, power settings and antivirus may affect both runs.

## Labelled real-data protocol

Collect independent, approved normal calibration sessions for each context. Train and freeze their profiles. In a separate test session, have the user explicitly label controlled activity and the start/end of introduced deviations without recording input/content. Export only the numerical feature vector, increasing timestamp, context and binary anomaly/drift ground truth. Use `scripts/evaluate_labelled.py` with the frozen store and the JSONL file. The script does not fit on test observations.

Temporal test segments must be continuous within a context; mark a new `segment` on context changes, pauses or missing observations. This avoids leakage across sessions. The same feature schema and window setting used in training are required. Labels represent the experimenter's behavioural judgment, not maliciousness.

For research conclusions, repeat across days, workloads and users with independent seeds/sessions; report confidence intervals and context recognition accuracy separately. Compare to a global Isolation Forest and non-temporal ablations only under equal data splits and compute budgets. These broader studies and adversarial/security claims are outside the measured results currently delivered.

The labelled JSONL schema is one object per observation: `timestamp` (UTC epoch seconds), `context` (one supported label), `segment` (continuity identifier), `features` (27 finite numbers in documented order), `feature_schema: 2`, `feature_window: 8` (or the trained value), `anomaly` and `drift` (explicit booleans). Missing labels are rejected. Example invocation: `python scripts/evaluate_labelled.py approved_test.jsonl --data-dir <frozen-private-store> --output reports/labelled_local.json`.

## Known statistical limits

The synthetic generator is simpler than actual operating systems, has known contexts and deliberately large shifts. The chronological holdout reduces leakage but does not create independent/exchangeable samples. Nominal alpha is a calibration target, not a guarantee. Finite rank distributions saturate in their extreme tails. Drift thresholds and the stability cutoff are documented research parameters requiring sensitivity analysis. The receptive-field guard reduces false spike-to-drift promotion at the cost of delay, and strict recovery resets can miss intermittent persistent changes.
